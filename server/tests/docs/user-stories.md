## US-001：用户在模拟支付模式下完成支付

**As** 一名开发测试人员（或开启模拟支付的普通用户），
**I want** 在不需要真实微信商户号和支付密码的情况下完成下单支付，
**So that** 我可以在测试/预发布环境中验证完整的购物流程。

### 验收标准
- [ ] 用户提交订单后，系统自动获取模拟支付参数（`mock: true`）
- [ ] 小程序检测到 `mock: true` 后跳过 `wx.requestPayment()` 调用
- [ ] 系统自动将订单状态从「待付款(0)」更新为「已付款(1)」
- [ ] 订单详情页显示「支付成功」状态
- [ ] `transaction_id` 字段以 `MOCK_TXN_` 前缀标记
- [ ] 整个模拟支付流程在 200ms 内完成（无真实网络请求）

### 关联测试用例
TC-PAY-02, TC-PAY-06

## US-002：用户在真实支付模式下完成支付

**As** 正式环境的普通用户，
**I want** 通过微信收银台安全地支付订单，
**So that** 我可以完成真实的购买行为并获得支付凭证。

### 验收标准
- [ ] 用户点击「去支付」后，系统调用微信统一下单接口获取真实 `prepay_id`
- [ ] 小程序通过 `wx.requestPayment()` 调起微信收银台
- [ ] 微信收银台关闭后（无论成功/取消），用户返回订单详情页
- [ ] 微信支付成功后，系统通过异步回调（`/pay/notify`）更新订单状态
- [ ] 支付失败/取消时，订单保持「待付款(0)」状态，用户可重新发起支付
- [ ] 支付金额与订单实付金额一致（精确到分）

### 关联测试用例
TC-PAY-09, TC-PAY-10

## US-003：管理员切换支付模式（核心：生产环境模拟测试）

**As** 系统管理员，
**I want** 在管理后台通过开关随时切换模拟支付 / 真实支付模式，
**So that** 我可以在生产环境不下线的情况下进行业务验收测试，
测试完成后一键切换回真实支付，无需重启服务。

### 验收标准
- [ ] 管理后台「系统设置 → 支付设置」显示当前支付模式
- [ ] 点击开关切换模式后，前端展示成功提示
- [ ] 切换操作写入数据库 `settings` 表（key=`pay_mock_mode`）
- [ ] 切换后**立即生效**（无需重启服务器）
- [ ] 下一个请求调用 `isMockMode()` 时读取最新 DB 设置
- [ ] 模拟模式下界面显示警告提示（橙色），真实模式显示成功提示（绿色）
- [ ] 未登录管理员无法访问切换接口（返回 401）
- [ ] 已禁用管理员账号无法切换（返回 401）

### 关联测试用例
TC-ADMIN-PAY-01, TC-ADMIN-PAY-02, TC-ADMIN-PAY-03, TC-ADMIN-PAY-04

## US-004：微信支付回调通知处理

**As** 微信支付系统，
**I want** 通过异步回调通知我们的服务器支付结果，
**So that** 商户系统能及时准确地更新订单状态并开始备货。

### 验收标准
- [ ] 回调接口对所有请求返回 HTTP 200（符合微信回调规范）
- [ ] 签名验证通过且 `result_code=SUCCESS` 时，订单状态更新为已付款
- [ ] 签名错误时，返回 `<return_code>FAIL</return_code>` 并记录日志
- [ ] 订单已处于已付款状态时，重复回调不触发二次更新（幂等性）
- [ ] `result_code=FAIL`（支付失败）时，不更新订单状态
- [ ] 回调中的 `transaction_id` 保存到订单记录

### 关联测试用例
TC-PAY-09, TC-PAY-10

## US-005：管理员审批退款

**As** 系统管理员，
**I want** 审批用户的退款申请时，系统自动调用微信退款接口，
**So that** 用户收到的退款是通过微信原路退回的，操作记录准确。

### 验收标准
- [ ] 管理员点击「同意退款」时，系统自动发起微信退款请求
- [ ] 模拟模式下：退款立即成功，无需真实商户证书
- [ ] 真实模式下：调用微信退款 API，退款金额 = 实付金额
- [ ] 退款成功后订单状态更新为「已退款(6)」
- [ ] 管理员点击「拒绝退款」时，订单恢复为「已付款(1)」
- [ ] 退款单号格式：`REF` + 订单号前缀，确保唯一性

### 关联测试用例
TC-ADMIN-REFUND-01（已在 admin 订单路由集成测试中覆盖）

## US-006：支付模式优先级控制

**As** 技术运维人员，
**I want** 通过环境变量设置默认支付模式，同时允许数据库配置在运行时覆盖，
**So that** 新环境部署时有合理默认值，同时运维人员能灵活调整无需重新部署。

### 优先级规则（高→低）
1. 数据库 `settings` 表 `pay_mock_mode` 字段（运行时，实时生效）
2. 环境变量 `WECHAT_PAY_MOCK=true/false`（进程启动时）
3. 内置默认：非 `production` 环境自动开启模拟模式

### 验收标准
- [ ] DB 设置为 `true` → `isMockMode()` 返回 `true`（无论 ENV 如何）
- [ ] DB 设置为 `false` → `isMockMode()` 返回 `false`
- [ ] DB 无记录 + `NODE_ENV=production` + `WECHAT_PAY_MOCK=false` → 返回 `false`
- [ ] DB 无记录 + `NODE_ENV=development` → 返回 `true`（安全默认）
- [ ] DB 查询异常时，回退到 ENV 值，不抛出错误（降级处理）

### 关联测试用例
TC-SVC-03, TC-SVC-04
